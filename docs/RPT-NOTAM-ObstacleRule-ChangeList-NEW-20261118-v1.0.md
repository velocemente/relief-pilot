## How the list was made

- **NavBlue/eOFP:** the whole OFP text of each fixture, split as TC-171-030 splits it (v1.13.0 and v1.14.0 split it identically). Each NOTAM evaluated alone, with no window (`etaMin` null: in effect) and at the TC-171-030 sweep (ORIG and DEST; ETA 0000, 0059, 0500, 1000, 1159, 1200, 1640, 2300, 2359Z; departure unknown, 0000Z, 1140Z; with and without the flight date). The whole-text split also yields pieces that are not one NOTAM (the OFP text before the first NOTAM, or a last NOTAM that runs on into the weather); they are listed with a note, as the corpus holds them. In the app each airport card reads its own NOTAM text, not these pieces.
- **FlightKeys:** each airport's `notamsRaw` (the NOTAM section as printed, type headings included) from the FlightKeys parser v0.3.0. v1.14.0 reads `notamsRaw` as it is: `_splitNotams()` cuts out the headings and every item carries its heading as `fkCategory`. v1.13.0 reads the same items without headings (the parser's `notams` text), as it would be given them — a heading inside v1.13.0 text joins the item above it (O-12). Each item alone, with no window and at each of its airport's windows (the briefing's role windows, at their midpoint, as TC-162 evaluates them).
- **Groups.** B and C compare the result with no window (the obstacle rule does not depend on time; at an airport window the NOTAM may also be out of effect — the windows are in the notes). U is every obstacle NOTAM v1.14.0 shows because the patterns cannot decide (`OBSTACLE_RULE.undecided`, a height near a procedure or a runway), whatever v1.13.0 did; the row says whether v1.13.0 showed it.
- The same NOTAM printed in several packages is listed once per package.
